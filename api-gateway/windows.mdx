Morpheus Skill Installation Guide (Windows)

**What you'll do:** Verify Node.js & Git → Get a Morpheus API key → Install WSL2 (Ubuntu) → Install OpenClaw → Install EverClaw → Import your API key → Remove the Bonjour plugin block → Restart the Gateway → Chat.

**Time:** About 20–30 minutes (the WSL2 install adds a restart cycle).

---

## Before You Start

**What this is, in one sentence:** installing OpenClaw (an AI agent CLI) and EverClaw
(the Morpheus inference skill) inside WSL2 so your agent can call Morpheus-hosted
models through the API Gateway — no wallet or local node required.

**What you'll need:**

| | Requirement |
|---|---|
| OS | Windows 10 (version 2004+) or Windows 11, with administrative privileges (software install + WSL configuration) |
| Hardware | 8 GB RAM (16 GB recommended), 20 GB free storage, multi-core CPU with virtualization enabled in BIOS/UEFI |
| Network | Internet access (dependencies, packages, AI model configurations) |
| Accounts | A Morpheus account, plus a Morpheus Inference API Key (you'll create the key in this guide) |
| Software | Node.js, Git, WSL2 (Ubuntu) — installed during this guide if not already present |

## Security Considerations

OpenClaw and EverClaw provide AI agents with access to local system resources. Before installation, users should understand the following security implications.

### 1. Local File & Command Access

AI agents may be able to:

- Read files within accessible directories
- Create or modify files
- Execute approved system commands

Only install trusted skills, review commands before approving execution, and avoid storing sensitive information in directories accessible to experimental agents.

### 2. API Key Protection

Treat API keys as confidential credentials. Do not:

- Share keys publicly
- Commit keys to Git repositories
- Include keys in screenshots or documentation

Store keys securely and regenerate them immediately if exposed.

### 3. Network Communications

Models accessed through Morpheus Gateway communicate with external inference providers over the internet. Users should be aware that:

- Prompts may be transmitted to remote AI services
- Provider privacy policies may differ
- Sensitive personal or corporate information should not be submitted without understanding the provider's data handling practices

### 4. Principle of Least Privilege & Resource Usage

Whenever possible:

- Use standard user accounts instead of administrator accounts
- Limit filesystem permissions
- Install only required skills and integrations

### 5. WSL2 Isolation

WSL2 provides an extra layer of isolation by running OpenClaw and EverClaw inside a separate Linux environment rather than directly on Windows. While it's not a replacement for good security practices, it helps contain any issues within the WSL2 environment and reduces the risk of affecting the main Windows installation.

## Installation

<Steps>
  <Step title="Verify Node.js Installation">
    Open Command Prompt or PowerShell and run:

    ```bash
    node --version
    ```

    If Node.js is installed and up to date, continue to the next step.

    Need to install Node?

    Navigate to the official Node.js Website: [Node.js — Download Node.js®](https://nodejs.org/en/download)

    Download the prebuilt Windows installer for:

    - Windows
    - x64 Architecture
    - Latest LTS or Current Release

    After installing Node.js, verify installation using:

    ```bash
    node --version
    ```

    **Node.js is ready.**
  </Step>

  <Step title="Verify Git Installation">
    Open Command Prompt or PowerShell and run:

    ```bash
    git --version
    ```

    If Git is installed, continue to the next step.

    Need to install Git? Download the latest version from the [official Git website](https://git-scm.com/download/win).

    After installation, verify with:

    ```bash
    git --version
    ```

    **Git is ready.**
  </Step>

  <Step title="Obtain a Morpheus API Key">
    Navigate to the [Morpheus website](https://mor.org).

    Click [Access Inference](https://app.mor.org).

    If you have an existing account, Sign In with your associated details. If not, click Sign Up at the bottom of the form and fill in the requested details.

    After successful registration, you'll be redirected to the Inference API Admin Page. Create a new API key.

    **Important:** copy and store your API key securely — it's only displayed once and cannot be viewed again after creation.
  </Step>

  <Step title="Installing WSL (Ubuntu)">
    <Warning>
      WSL2 is required for this guide — EverClaw only supports macOS, Linux, and
      Windows via WSL2. Native Windows shells (PowerShell, Command Prompt, Git
      Bash, MSYS, Cygwin) are not supported, even though OpenClaw itself may run
      there.

      Complete all remaining steps inside the WSL2 Ubuntu terminal, not
      PowerShell — PowerShell is only used here to install WSL2 itself.
    </Warning>

    Open PowerShell as Administrator and run:

    ```bash
    wsl --install
    ```

    Wait for Windows to:

    - Enable WSL
    - Install the Linux kernel
    - Configure WSL 2 as default
    - Install Ubuntu

    Restart your computer when prompted.

    ### Create Your Ubuntu User

    After rebooting, open Ubuntu from the Start Menu and:

    - Enter a username
    - Enter a password
    - Confirm the password

    <Note>
      Password characters won't appear while typing — this is normal.
    </Note>

    ### Launch Ubuntu

    Open PowerShell and enter `wsl` to open your Ubuntu environment.

    Update Ubuntu:

    ```bash
    sudo apt update && sudo apt upgrade -y
    ```

    **WSL2 Ubuntu is installed and up to date.**
  </Step>

  <Step title="Install OpenClaw">
    Inside Ubuntu, run:

    ```bash
    curl -fsSL https://openclaw.ai/install.sh | bash
    ```

    Wait for the installation to complete.

    **OpenClaw is installed.**
  </Step>

  <Step title="OpenClaw Onboarding">
    Run:

    ```bash
    openclaw onboard --install-daemon
    ```

    The wizard walks you through choosing a model provider, setting an API key, and configuring the Gateway. It takes about 2 minutes.

    - **First option:** select Yes
    - **Setup mode:** select QuickStart
    - **Model/auth provider:** select Skip for now
    - **Default model:** select Keep current model — the default (`mor-gateway/glm-5`) works out of the box with a funded key; see [Model Configuration](#model-configuration) below if you later want to switch or add models
    - **Select channel:** select Skip for now
    - **Search Provider:** select Skip for now
    - **Configure skills:** select No
    - **Enable Hooks:** enable all of them like shown
    - **Hatch your agent:** select Hatch later

    **Onboarding wizard complete.**
  </Step>

  <Step title="Install EverClaw (Morpheus Skill)">
    Inside Ubuntu, run:

    ```bash
    curl -fsSL https://get.everclaw.xyz | bash
    ```

    Or

    ```bash
    curl -fsSL https://raw.githubusercontent.com/EverClaw/EverClaw/main/packages/core/scripts/install-with-deps.sh | bash
    ```

    Wait for the installation to complete successfully. The installer will:

    - Verify dependencies
    - Install EverClaw
    - Configure OpenClaw integration
    - Provision a temporary bootstrap inference key
    - Configure local fallback options

    **EverClaw is installed.**
  </Step>

  <Step title="Import Your Morpheus API Key">
    Navigate to the EverClaw directory:

    ```bash
    cd ~/.openclaw/workspace/skills/everclaw
    ```

    <Note>
      The installed directory is confirmed `everclaw` (verified via fresh-install
      testing on OpenClaw 2026.7.1-2). If it's missing, run
      `ls ~/.openclaw/workspace/skills/` and use whichever directory is present.
    </Note>

    <Note>
      EverClaw's installer (previous step) may already have provisioned a bundled
      temporary starter key in `evcl-...` format — this is different from your
      own Morpheus API key (`sk...` format) from the Obtain a Morpheus API Key
      step above. For this step, use your `sk-...` key, not the bundled
      `evcl-...` one — the bundled key is a fallback, not a replacement for your
      own account key.
    </Note>

    Run:

    ```bash
    npm run bootstrap -- --key sk-XXXXXXXXXXXXXXXX
    ```

    (Replace sk-XXXXXXXXXXXXXXXX with your own Morpheus API key from the Obtain a Morpheus API Key step above.)

    <Note>
      If this fails with an "insufficient credits" error on a newly created account,
      see [Insufficient Credits During Bootstrap](#insufficient-credits-during-bootstrap)
      in Troubleshooting below — note that a confirmed fix for this has not been
      validated on a genuinely fresh, unfunded account.
    </Note>

    If successful, EverClaw should display:

    ```
    Morpheus API Gateway configured!
    ```
  </Step>

  <Step title="Remove the Bonjour Plugin Block (Required)">
    <Warning>
      On OpenClaw `2026.7.1-2`, the config generated by onboarding includes a
      `gateway.plugins.bonjour` block that fails schema validation. If this step is
      skipped, the next step (`openclaw gateway restart`) will refuse to start:

      ```
      Invalid config at ~/.openclaw/openclaw.json:
      - gateway: Invalid input
      OpenClaw config is invalid
      Fix: openclaw doctor --fix
      Gateway aborted: config is invalid.
      ```

      This is a required step on this version, not optional cleanup.
    </Warning>

    Open the configuration file:

    ```bash
    nano ~/.openclaw/openclaw.json
    ```

    Locate and remove the following block:

    ```json
    "plugins": {
      "bonjour": {
        "enabled": false
      }
    }
    ```

    Save the file:

    ```bash
    Ctrl + X
    Y
    Enter
    ```

    Then validate before moving on:

    ```bash
    openclaw config validate
    ```

    You should see `Config valid: ~/.openclaw/openclaw.json`. If it still reports
    invalid, check that the block above was removed completely (including its
    surrounding comma) and didn't leave the JSON malformed.

    <Note>
      The error output above suggests `openclaw doctor --fix` as an automatic
      remedy. That path was not exercised while validating this guide — manual
      removal followed by `openclaw config validate` is what was actually tested.
      If you try `openclaw doctor --fix` instead, still confirm the result with
      `openclaw config validate` afterward.
    </Note>
  </Step>

  <Step title="Restart the Gateway">
    Restart OpenClaw:

    ```bash
    openclaw gateway restart
    ```

    If restart fails:

    ```bash
    openclaw gateway stop
    ```

    And then:

    ```bash
    openclaw gateway start
    ```

    **Gateway restarted successfully.**
  </Step>

  <Step title="Launch OpenClaw Chat">
    Run:

    ```bash
    openclaw chat
    ```

    Send a test message and confirm you get a response.

    **You should now be able to use Morpheus models through EverClaw.**

    <Frame>
      <img src="/api-gateway/images/api-gateway-windows-guide-01-first-response.png" alt="OpenClaw chat session showing a successful first response from a Morpheus-hosted model through the API Gateway" />
    </Frame>
  </Step>
</Steps>

## Model Configuration

By default, EverClaw configures `mor-gateway/glm-5` as your primary model, and it
works out of the box with a funded Morpheus API key — you do not need to change it
to get a working setup. This section is optional reference for anyone who wants to
switch models or add one that isn't provisioned by default.

### Models Available After Bootstrap

Running `npm run bootstrap` (in the **Import Your Morpheus API Key** step above)
registers a handful of models under the `mor-gateway` provider automatically:

| Model | Ready to use after bootstrap? |
|---|---|
| `mor-gateway/glm-5` (default) | Yes |
| `mor-gateway/kimi-k2.5` | Yes |
| `mor-gateway/glm-4.7-flash` | Yes |
| `mor-gateway/llama-3.3-70b` | Declared, but missing an alias entry — see below |
| `mor-gateway/deepseek-v4-flash` | Not declared at all — needs the full addition below |

### Switching the Active Model

Use the CLI or the in-chat slash command to change which model is active — you do
not need to hand-edit `openclaw.json` just to change the primary model:

```bash
openclaw models set mor-gateway/kimi-k2.5
```

or, from inside an OpenClaw chat session:

```
/model mor-gateway/kimi-k2.5
```

Both persist across `openclaw gateway restart` and across new sessions started
with `/new`.

<Note>
  `openclaw models list`, `openclaw models status`, and `openclaw models
  fallbacks` are also available for inspecting current model and fallback
  configuration from the CLI.
</Note>

### Adding a Model That Isn't Fully Provisioned

To use a model bootstrap didn't fully provision (for example
`mor-gateway/deepseek-v4-flash`, or to finish setting up
`mor-gateway/llama-3.3-70b`), two changes to `~/.openclaw/openclaw.json` are
needed:

**1. Declare the model under `models.providers.mor-gateway.models`** (skip this
part if it's already declared, as with `llama-3.3-70b`):

```json
{
  "id": "deepseek-v4-flash",
  "name": "DeepSeek V4 Flash (via Morpheus Gateway)",
  "reasoning": false,
  "input": ["text"],
  "cost": { "input": 0, "output": 0, "cacheRead": 0, "cacheWrite": 0 },
  "contextWindow": 131072,
  "maxTokens": 8192
}
```

**2. Add an alias entry under `agents.defaults.models`:**

```json
"mor-gateway/deepseek-v4-flash": {
  "alias": "DeepSeek V4 Flash (Gateway)",
  "streaming": true
}
```

Then validate and restart:

```bash
openclaw config validate
openclaw gateway restart
```

Once declared, make the model active with `openclaw models set` or `/model` (see
above) — don't hand-edit a `primary` field to switch models.

If you already have a session open, start a new one so it picks up the change:
`/new mor-gateway/deepseek-v4-flash`.

## Diagnostics

EverClaw ships a diagnostic script that checks your setup end-to-end:

```bash
bash ~/.openclaw/workspace/skills/everclaw/scripts/diagnose.sh
```

<Note>
  If you're following this guide (API Gateway only, no Morpheus proxy-router / P2P
  components installed), expect several checks to report as failed. That's
  expected — the script also tests the Native/P2P path, which this guide doesn't
  set up. A result like "10 passed, 1 warning, 5 failures" can still mean a fully
  healthy Gateway-only install.
</Note>

### Failures That Are Expected in Gateway-Only Mode

Safe to ignore if you're following this guide — they indicate the Native/P2P path
isn't installed, not that the Gateway path is broken:

- `Proxy-router not responding` (port 8082)
- `Morpheus proxy not responding` (port 8083)
- Inference test timeout against `morpheus/kimi-k2.5` (this targets the P2P path)
- `Auth profiles file not found` (warning)

The check that actually confirms your Gateway install is working is:

```
✅ Morpheus API Gateway reachable (api.mor.org → HTTP 200)
```

### Failures Worth Acting On

- **Models with `reasoning: true` (causes HTTP 400)** — set `"reasoning": false`
  for the affected model under `models.providers.mor-gateway.models` in
  `~/.openclaw/openclaw.json`.
- **Models missing `streaming: true`** — can cause timeouts on slow connections.
  Run `node ~/.openclaw/workspace/skills/everclaw/scripts/setup.mjs --apply`, or
  add `"streaming": true` manually (see [Model Configuration](#model-configuration)
  above).

After making changes, restart the gateway: `openclaw gateway restart`.

## Troubleshooting

### Insufficient Credits During Bootstrap

<Warning>
  This has not been re-confirmed on a genuinely fresh, unfunded account — the most
  recent validation pass used a pre-funded account, so this failure mode itself
  was not reproduced or re-tested. The workaround below is carried over from
  earlier reports as a best-effort suggestion, not a validated fix.
</Warning>

If `npm run bootstrap -- --key sk-...` fails with an "insufficient credits" error:

**Suggested workaround (unverified):** skip `npm run bootstrap` and instead add
your Morpheus API key directly under `models.providers.mor-gateway.apiKey` in
`~/.openclaw/openclaw.json`, then continue to the **Remove the Bonjour Plugin
Block** step.

If this doesn't resolve it, treat it as an account/credits issue on the Morpheus
side rather than a setup mistake.

### EverClaw shows "needs setup" / "visible to model: no" even after being enabled

Some installed versions of EverClaw's SKILL.md declare optional environment variables as objects, but the running OpenClaw version may expect `requires.env` as a plain string array. This mismatch can show as:

```
environment: ✗ [object object], ✗ [object object]
```

**Fix:**
1. Open the skill's `SKILL.md` (in the `everclaw` directory) and back it up.
2. Remove the `env:` block under `requires:`, keeping `bins:`.
3. Run `openclaw gateway restart && openclaw skills info everclaw`.

Expect `ready` and `visible to model: yes` when fixed.

### Asking the model to use EverClaw doesn't seem to do anything

EverClaw is not a `/everclaw` slash command. It installs a permanent inference connection used automatically for ordinary chat — no invocation needed — and separately ships a diagnostic/setup skill that only activates for matching natural-language requests, e.g. "use the everclaw skill to perform a read-only diagnosis of my morpheus setup."

**To verify the skill itself is working:** run `openclaw skills info everclaw` and look for `ready` and `visible to model: yes`, rather than relying on the model's own claims.
